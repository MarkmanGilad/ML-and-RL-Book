### לולאה אחת לשלוש שאלות בינאריות

נפריד בין אלגוריתם האימון, שנשאר קבוע, ובין כלל יצירת התווית. הפונקציה מקבלת את הכלל הזה כארגומנט. כך אפשר להשתמש באותו קוד עבור שמלה או עבור ספרה, ולהבטיח שגם הבדיקה תשתמש באותה הגדרה.

<div class="code-panel" dir="ltr">

```python
def train_binary(model, train_data, test_data, target_rule,
                 epochs, batch_size, lr):
    model = model.to(device)
    train_loader = DataLoader(train_data, batch_size=batch_size,
                              shuffle=True)
    test_loader = DataLoader(test_data, batch_size=batch_size)
    optimizer = torch.optim.Adam(model.parameters(), lr=lr)
    for epoch in range(epochs):
        model.train()
        for images, labels in train_loader:
            x = images.reshape(-1, 784).to(device)
            y = target_rule(labels).float().reshape(-1, 1)
            y = y.to(device)
            optimizer.zero_grad()
            loss = nn.functional.binary_cross_entropy(model(x), y)
            loss.backward()
            optimizer.step()
    model.eval()
    correct = total = 0
    with torch.no_grad():
        for images, labels in test_loader:
            x = images.reshape(-1, 784).to(device)
            predicted = model(x).flatten().cpu() >= 0.5
            expected = target_rule(labels)
            correct += (predicted == expected).sum().item()
            total += len(labels)
    return model, correct / total
```

</div>

### Fashion-MNIST: שמלה או לא שמלה

אפשר להשתמש באותו רעיון של זיהוי 7 כדי לזהות **שמלה**, שתוויתה 3 במאגר Fashion-MNIST. כל תמונה היא שוב 28×28 בגוני אפור.

### פירוש התווית חשוב יותר משם המאגר

ב־Fashion-MNIST יש עשר קטגוריות מקוריות, אך במשימת שמלה־או־לא־שמלה נלמד רק פלט אחד. ערך 1 שהמודל מחזיר אינו ״הקטגוריה מספר 1 במאגר״ אלא ״כן, זו שמלה״. לכן בהצגת תמונה צריך להבחין בין מספר הקטגוריה המקורי לבין התשובה הבינארית.

| משימה | תווית חיובית | צורת פלט |
|---|---|---|
| MNIST: הספרה 7 | `labels == 7` | `[batch,1]` |
| Fashion-MNIST: שמלה | `labels == 3` | `[batch,1]` |
| EMNIST: ספרה | `labels < 10` | `[batch,1]` |

בכל מעבר מאתחלים מודל ואופטימייזר חדשים ומגדירים טוענים למאגר החדש. שינוי `required_label` רק בתא אחד והשארת התנאי הקודם בבדיקה ייצור הערכה של משימה אחרת.

### לראות את התו המקורי ב־EMNIST

<div class="code-panel" dir="ltr">

```python
def emnist_character(label):
    if 0 <= label <= 9:
        return chr(ord('0') + label)
    if 10 <= label <= 35:
        return chr(ord('A') + label - 10)
    if 36 <= label <= 61:
        return chr(ord('a') + label - 36)
    raise ValueError("Invalid byclass label")
```

</div>

ההמרה עוזרת להשוות את התמונה לתווית המקורית. האימון הבינארי עדיין שואל רק ספרה או אות. יש סימנים דומים חזותית, כגון האות O והספרה 0; קריאת טעויות כאלה מלמדת מה המשימה דורשת מעבר לירידה בהפסד.

מחברות התרגול הלא־פתורות בונות את תאי הנתונים והמסגרת, אך אינן ניסוי מוצלח נוסף. הפתרון הוא להשלים את אותו רצף של הכנה, מודל, הפסד, אימון ובדיקה שהודגם כאן, תוך שמירה על משמעות התווית בכל התאים.
