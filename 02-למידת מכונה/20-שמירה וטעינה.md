[פתיחת מחברת Colab 1](https://colab.research.google.com/drive/1TiUZz2nB2WrFiKWyXJK_AT-l8W0NUhy7?usp=sharing)

**חומרי הליווי:** [10.שמירה וטעינה של מודלים](../../../sources/ML/10.%D7%A9%D7%9E%D7%99%D7%A8%D7%94%20%D7%95%D7%98%D7%A2%D7%99%D7%A0%D7%94%20%D7%A9%D7%9C%20%D7%9E%D7%95%D7%93%D7%9C%D7%99%D7%9D.pptx) · [10_Model_Save](../../../sources/ML/converted/10_Model_Save/notebook.md)


### מה צריך לשמור?

אימון משנה את הפרמטרים של המודל בזיכרון. כדי להשתמש בתוצאה אחרי סגירת סביבת הריצה צריך לשמור אותם לקובץ. קוד המחלקה מתאר את המבנה; המשקלים הם הערכים שנלמדו.

הדוגמאות בפרק ממשיכות עם **model מסוג DigitNet**, שאומן בפרק ב.17. נציג את שתי הדרכים שבמצגת: שמירת אובייקט המודל, ואז שמירת הפרמטרים בלבד.

### המבנה, המשקלים והנתונים שמסביב

אפשר לחשוב על המחלקה כעל שרטוט מכונה, ועל המשקלים כעל הכוונון שנלמד. שני מופעים מאותה מחלקה מתחילים בדרך כלל בכוונון שונה. כדי לשחזר תחזית אין די לדעת שהיו ״שתי שכבות״; צריך גם את ממדיהן, האקטיבציות, המשקלים ואופן הכנת הקלט.

מחברת השמירה משתמשת ברשת 784→200→10, ואילו מודל DigitNet בפרק ב.17 כולל גם שכבה של 100 יחידות. כל אחד ניתן לשמירה, אך אי אפשר להטעין את משקלי האחד לתוך מבנה האחר ולצפות להתאמה. דוגמאות הקוד כאן ממשיכות את DigitNet, ושמות הפרמטרים בקובץ חייבים להתאים אליו.

### שמירת המודל כולו

<div class="code-panel" dir="ltr">

```python
torch.save(model, "digit_model.pth")
```

</div>

טעינה בדרך זו דורשת שסביבת פייתון תכיר את המחלקה DigitNet. הטעינה הבאה מיועדת **לקובץ שאתם עצמכם שמרתם ושאתם סומכים עליו**:

<div class="code-panel" dir="ltr">

```python
loaded_model = torch.load(
    "digit_model.pth",
    map_location=device,
    weights_only=False
)
loaded_model.eval()
```

</div>

האפשרות weights_only=False מאפשרת טעינת אובייקט פייתון שלם. אין להשתמש בה עבור קובץ לא מהימן, משום שפתיחתו עשויה להפעיל קוד. בגרסאות PyTorch חדשות ברירת המחדל מגבילה את הטעינה; זו הסיבה ששורת טעינה ישנה עשויה להיכשל. [תיעוד השמירה והטעינה](https://docs.pytorch.org/docs/stable/notes/serialization.html).

### שמירת state_dict

**state_dict** הוא מילון של הפרמטרים והמצב הרשום של המודל. זו הדרך המתאימה כאן לשמירה ברורה של המשקלים, בנפרד מהקוד שמגדיר את הרשת.

<div class="code-panel" dir="ltr">

```python
torch.save(model.state_dict(),
           "digit_weights.pth")
```

</div>

בעת הטעינה יוצרים מודל בעל אותו מבנה ומטעינים את המשקלים לתוכו:

<div class="code-panel" dir="ltr">

```python
loaded_model = DigitNet().to(device)
state = torch.load(
    "digit_weights.pth",
    map_location=device,
    weights_only=True
)
loaded_model.load_state_dict(state)
loaded_model.eval()
```

</div>

מספרי השכבות, ממדיהן ושמותיהן צריכים להתאים לקובץ השמור. map_location קובעת לאיזה התקן ייטענו הטנסורים, למשל CPU גם אם האימון בוצע על GPU.

### בדיקת תחזית לאחר טעינה

<div class="code-panel" dir="ltr">

```python
images, labels = next(iter(test_loader))
model.eval()
with torch.no_grad():
    x = images.to(device)
    original = model(x)
    restored = loaded_model(x)
    print(torch.allclose(original, restored))
    predicted = restored.argmax(dim=1)
    print(predicted[:6].cpu())
```

</div>

הבדיקה משווה את פלטי אותו מודל לפני השמירה ואחריה. התאמה של המשקלים ושל אופן החישוב אמורה לשמר את התחזיות; אין צורך לאמן מחדש כדי להשתמש במשקלים שנטענו.

### שמירה ב־Google Drive

קובץ בתיקיית העבודה הזמנית של Colab עלול להיעלם עם סיום סביבת הריצה. לשמירה מתמשכת אפשר לחבר את Drive, לאשר את החיבור בחשבון שלכם ולבחור תיקייה:

from google.colab import drive

אם המודל דורש נרמול, צריך לשמור גם את פרמטרי ההכנה ולהשתמש בהם בעת החיזוי. שמירת משקלים בלבד אינה מתעדת אוטומטית את כל תהליך הכנת הנתונים.

### לשמור נקודת המשך לאימון

שמירת משקלים מאפשרת חיזוי. כדי להמשיך אימון של Adam כדאי לשמור גם את מצב האופטימייזר, שמכיל מידע על היסטוריית הנגזרות. אפשר לשמור מילון עם הטנסורים והמידע הפשוט הדרוש לשחזור הניסוי.

<div class="code-panel" dir="ltr">

```python
checkpoint = {
    "model": model.state_dict(),
    "optimizer": optimizer.state_dict(),
    "completed_epochs": 5,
    "class_names": [str(i) for i in range(10)],
    "input_shape": [1, 28, 28],
    "preprocessing": "ToTensor, values in [0,1]",
}
torch.save(checkpoint, "digit_checkpoint.pth")

saved = torch.load("digit_checkpoint.pth",
                   map_location=device, weights_only=True)
restored = DigitNet().to(device)
restored.load_state_dict(saved["model"])
restored_optimizer = torch.optim.Adam(
    restored.parameters(), lr=0.01
)
restored_optimizer.load_state_dict(saved["optimizer"])
restored.train()
```

</div>

לפני שמירה יש לוודא שמספר התקופות הרשום אכן תואם לאימון שבוצע. לצורך המשך זהה לחלוטין עשוי להידרש גם מצב האקראיות וסדר טעינת הנתונים; המילון מדגים את רכיבי ההמשך הבסיסיים. לחיזוי בלבד אין צורך לשחזר אופטימייזר, ומשתמשים במצב eval.

### לבדוק שחזור, לא רק קיום קובץ

קובץ שנוצר בהצלחה עדיין יכול להכיל מודל אחר מזה שהתכוונו לשמור. נבדוק את פלטי המודל המקורי והמשוחזר על אותו קלט, באותו מצב הערכה ובאותו עיבוד. אם יש אי־התאמה, נבדוק קודם מבנה ושמות שכבות, נרמול, התקן וסדר הקטגוריות. פלט שמצביע על הקטגוריה 3 אינו מועיל אם טבלת השמות נטענה בסדר שונה.

בקובץ שמירה של רגרסיה יש לצרף את מינימום וטווח הקלט, ואם נורמל היעד גם את פרמטריו. אלה אינם נלמדים מחדש עבור כל תחזית. בסיום עבודה ב־Colab שומרים את הקובץ למיקום מתמשך לפני שסביבת הריצה נסגרת.
